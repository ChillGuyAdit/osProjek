Konsep Sistem Operasi yang Diterapkan

Bagaimana konsep OS diimplementasikan dalam sistem penjadwalan sidang ini

Resource Management

Dosen dan ruang sidang dianalogikan sebagai resource terbatas dalam OS. Setiap resource hanya bisa dialokasikan ke satu proses pada satu waktu (mutual exclusion).

Dosen → CPU/Printer Ruang → Memory/Disk

Process Scheduling

Sidang mahasiswa dianalogikan sebagai proses yang membutuhkan alokasi resource. Setiap proses memiliki state: PENDING (Ready), TERJADWAL (Running), GAGAL (Blocked).

Sidang → Process Antrian → Ready Queue

Deadlock Avoidance

Fungsi cek_konflik() mengimplementasikan Banker's Algorithm. Sebelum mengalokasikan resource, sistem memeriksa apakah alokasi tersebut akan menyebabkan konflik (unsafe state).

cek_konflik → Safety Check Konflik → Unsafe State

Mutual Exclusion

Satu dosen tidak boleh menguji dua sidang bersamaan, satu ruang tidak boleh dipakai dua sidang bersamaan. Ini adalah implementasi critical section pada resource.

1 Dosen → 1 Sidang/waktu 1 Ruang → 1 Sidang/waktu

Recovery & Rescheduling

Ketika sidang gagal karena konflik, sistem menyarankan slot waktu alternatif terdekat. Mirip rescheduling di OS ketika proses gagal mendapat resource.

Saran Slot → Rescheduling Alternatif → Recovery

Resource Allocation Table

Database menyimpan tabel alokasi resource: siapa menggunakan apa dan kapan. Mirip allocation matrix pada Banker's Algorithm di OS.

DB → Allocation Matrix Relasi → Assignment Edge
